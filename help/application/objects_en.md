# Creating objects

APRS objects let you manually publish information about fixed or temporary points in the APRS network. These may include repeaters, gateways, field points, event locations, warnings, or other places relevant to APRS users.

This screen is used to create, edit, and transmit APRS objects from the application.

## Repeater and QSY objects

A special case of APRS objects is objects that describe repeaters and QSY frequencies. When creating them, it is worth following established naming and formatting rules, because many APRS radios can recognize such objects and present them to the user in a convenient form.

The description of best practices for such objects is available in a separate document:

[Repeater and QSY objects](../protocoll/repeaters_qsy_en.md)

## Practical notes

- The object name should be unambiguous across the APRS-IS network.
- For permanent objects, avoid names that can easily conflict with objects from other regions.
- For temporary objects, it is worth using names that are clear to local users.
- The comment text should be short, specific, and useful on a radio or APRS client screen.
- Objects transmitted over radio should be sent at a reasonable frequency so they do not unnecessarily occupy the channel.
