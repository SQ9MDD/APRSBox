# Packet routing rules

This screen lists the rules that APRSBox uses to move APRS packets between inputs and outputs. A rule has one source, optional filters in the middle, and one target.

Rules are evaluated from top to bottom. The order on the list matters, especially when several rules describe similar traffic.

## Common uses

- forward RF-received frames to APRS-IS,
- digipeat RF traffic to an RF output,
- forward locally generated APRSBox frames to APRS-IS,
- log selected traffic without transmitting it,
- drop traffic that should not continue.

## Sources and targets

`Receiver RF` means packets received by a configured radio modem.

`Local TX` means frames generated by APRSBox itself, such as beacons, status packets, weather, objects, items, bulletins and messages.

Targets include `TX RF`, `TX APRS-IS`, `Black Hole` for log-only handling, and `Action Drop` for ending the rule with a drop.

`Local TX` can be routed only to APRS-IS or to log-only handling.

## Filters

Filters run in order. If a packet is rejected by a filter, later steps are not executed.

Useful filters include:

- `Strict Filter` rejects `TCPIP`, `TCPXX`, `NOGATE`, `RFONLY` and invalid third-party packets.
- `Path rule and DIGI guard` handles the digi path and blocks frames this station should not repeat.
- `Duplicate Filter` provides a short viscous-delay window.
- `Direct Only` accepts only directly heard packets.
- callsign, digi, packet type, icon, distance and rate-limit filters narrow the traffic before transmission.

## System guards

`TX APRS-IS` rules are system-restricted to a mandatory `Strict Filter`.

`TX RF` rules require an enabled `Path rule and DIGI guard` step.

Only one enabled rule can handle the same source-target pair at a time.
